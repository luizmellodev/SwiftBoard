SwiftBoard

You register scenarios (component + named state) in Swift. This page is a live view of the running process — unless you exported a static copy.

Products

  • SwiftBoardServer — gallery for a design system you own. Link only this.
  • SwiftBoardKit — same gallery, pre-filled with SwiftDS. Call SwiftBoardKit.registerAll(). Do not copy a registrar. SwiftDS is a separate UI library; fork it to change how controls look.

One package URL. Pick the product in Xcode. Same repo README for install snippets.

Start the gallery

Your production UI stays as-is. On the root view, DEBUG only:

#if DEBUG
.swiftBoard {
    BoardScenarios.registerAll()          // own DS
    // SwiftBoardKit.registerAll()        // SwiftDS catalog instead (or as well)
}
#endif

That starts the HTTP server and shows a badge. Tap it for the in-app sheet; copy the URL for Safari/Chrome on the Mac (http://127.0.0.1:8080). Stop the app → localhost dies. Prefer Simulator first. On a physical iPhone add NSLocalNetworkUsageDescription.

Without the badge: registerAll() then try await BoardServer().start() in a .task. Server is DEBUG-only unless SWIFTBOARD_ENABLE=1.

Register (own components)

Nothing is auto-discovered. The view itself should not import SwiftBoard — only the DEBUG extension, like a #Preview:

#if DEBUG
import SwiftBoardServer

extension AppButton: BoardScenarioProvider {
    static func provideScenarios(into board: SwiftBoard) {
        board.addScenarios(
            category: "Actions",
            component: "Button",
            summary: "Primary tappable action.",
            parameters: [ScenarioParameter(name: "title", type: "String")]
        ) {
            Scenario("Primary", docs: ScenarioDocs(snippet: "AppButton(title: \"Continue\")")) {
                AppButton(title: "Continue")
            }
        }
    }
}
#endif

Then a type list (one line per component, not per state):

SwiftBoard.shared.addScenarios(from: [AppButton.self, AppBadge.self])

summary / parameters / ScenarioDocs(snippet:) are optional; without them you still get cards. Same category+component appends states. Delete the registration and restart to remove — nothing is stored on disk.

Rebuild/run after Swift changes, then reload this tab. No live-reload.

Hosted site for the team (static export)

This live server is not a public URL. For Vercel / Netlify / S3 you export a static snapshot: HTML + CSS + JS + PNG screenshots.

Running the app does not update a site already hosted. New components (e.g. DS 0.0.1 → 0.0.2) need a new export, then you replace the files on the host.

  1. Register the new work. Rebuild on a Mac or iOS Simulator (export cannot run on Linux/Vercel — it renders SwiftUI).
  2. Export, which rewrites a folder (full tree, not a patch): 
    try await StaticExporter.export(to: URL(fileURLWithPath: "./site"))
    From the SwiftBoard repo: SWIFTBOARD_EXPORT=./site swift run SwiftBoardDemo
  3. Upload the entire folder: index.html, CSS/JS, manifest.json, docs.html, and snapshots/. HTML alone is not enough.
  4. Deploy that directory. Designers use the public link. No app needs to be running.

Optional: macOS CI that exports then deploys. Open the folder via file:// to preview before upload.

In-app gallery

.swiftBoard already presents BoardGallery from the badge. Same registry, live SwiftUI instead of PNGs. Product SwiftBoard if you want the sheet with no HTTP server.

iOS vs Mac rendering

swift run SwiftBoardDemo uses macOS controls. For iOS-accurate snapshots, run the app in Simulator (this repo: Scripts/run-ios-demo.sh). The Mac browser still uses http://127.0.0.1:8080.
